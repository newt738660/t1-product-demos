# T1 V2.2 基础角色与组织权限产品方案 V0.1

日期：2026年10月3日  
对应任务：V2.2基础角色与组织权限需求完善  
状态：轻量方案及交互评审稿；不代表生产功能已上线或需求评审已通过。

## 一、范围与基本关系

本期只设三类固定角色：**管理员、投放人员、财务人员**。沿用已有成员协作方案，不建设复杂组织系统，不保留此前预研和Demo中扩展的其他可选角色。

- 登录用户代表具体人员，每个人使用自己的账号，不共用管理员密码。
- 组织是围绕同一广告主的成员集合。本期界面仅管理当前关联的一个广告主，不增加部门层级、多组织或多广告主切换。
- 成员通过已有绑定关系或管理员邀请获得访问资格，再按角色使用功能。同一广告主的成员不按“本人创建”隔离广告和报表。
- 一名成员对应一个角色，一个广告主保留一名管理员。角色只控制T1已开放的能力，不扩大广告主对SSP资源的操作权。
- 移除成员、调整角色和交接管理员均不改变广告归属、余额、投放状态及历史数据。

## 二、三类角色与权限

| 功能 | 管理员 | 投放人员 | 财务人员 |
| --- | --- | --- | --- |
| RTB创建、编辑、启停、归档 | 可以 | 可以 | 不可以 |
| CPD允许修改的创意及版本查看 | 可以 | 可以 | 不可以 |
| 投放详情、效果报表与导出 | 可以 | 可以 | 不可以 |
| 效果报表中的曝光、点击、CTR及RTB消耗 | 可以 | 可以 | 不可以 |
| 账户余额、充值申请、充值记录及凭证 | 可以 | 不可以 | 可以 |
| 财务消耗记录查询及导出 | 可以 | 不可以 | 可以 |
| 邀请、调整角色、移除及管理员交接 | 可以 | 不可以 | 不可以 |
| 本人账号验证、组织关系、帮助及联系运营 | 可以 | 可以 | 可以 |

**区分投放消耗与充值账务：** 投放人员需要通过效果报表查看投放消耗，但不因此获得充值记录、付款凭证和财务管理权限。财务人员在财务页面查询消耗，不通过该页面获得投放编辑或完整效果报表权限。

管理员同样不能修改运营管理的CPD计划、资源排期、价格，也不能自行批准充值到账。暂停、归档、创意审核等继续遵循对应模块原规则。

## 三、存量用户的默认管理员

### 1. 已确认规则

**同一广告主下，最早成功绑定该广告主的用户，默认设为管理员。**

按绑定成功时间比较，不按账号注册时间、提交申请时间、姓名、成员列表顺序或本次登录顺序判断。其他广告主的绑定记录不参与比较；失败、驳回、待审核的绑定申请不算成功绑定。

例如：用户甲先注册，但用户乙先成功绑定这个广告主，则乙为默认管理员。

### 2. 只初始化一次

默认分配在存量迁移时执行一次并保留分配依据。之后已完成管理员交接的，以现任管理员为准；重新登录、刷新或换邮箱都不能恢复成最早绑定用户。已有明确、可核验的管理员交接记录，也不能被本次默认分配覆盖。

管理员不能直接将自己移除或通过普通角色调整取消自己的管理员身份，应先完成交接，避免无人管理或同时出现两名管理员。

### 3. 无法可靠判断时

以下情况标记“管理员待核对”，由运营核验历史绑定记录及账户归属：

- 成功绑定记录缺失、时间无效，无法完整比较。
- 多人最早成功绑定时间相同，现有记录不能证明先后。
- 最早绑定用户已停用、被移除或无法核验有效身份。

不自动把第二个用户、当前登录用户或列表第一行提升为管理员。异常期间不新增成员管理权限，原有投放及历史数据保持不变。运营纠正归属的后台能力不在本次Demo中伪造为已实现。

### 4. 其他存量成员

已有角色能明确对应投放人员或财务人员的，沿用对应权限；无明确角色或旧只读成员，由管理员分配为投放人员或财务人员。

等待分配期间，页面显示“待分配角色”，只保留可核实的原有访问与操作权限，不自动升级；原权限也无法核实的，不新增广告主数据访问权，联系管理员处理。**这是存量过渡状态，不是第四种可选角色。**

管理员为其分配角色后，立即按新角色生效；原有权限快照不继续叠加。原管理员完成交接后也不再保留管理员权限。

## 四、页面及成员操作

### 1. 组织与成员

管理员可查看当前广告主、现任管理员、完整成员列表及操作记录；成员列表展示姓名、邮箱、角色、成员状态、首次成功绑定时间和操作入口。管理员可展开查看默认分配依据。

非管理员仅查看自己的成员关系、角色、权限说明及管理员联系信息，不展示全员列表和全量操作记录。“待分配角色”及“管理员待核对”提供明确说明，不伪装成正常已分配状态。

本期保留一个“查看角色权限”入口，直接展示三角色固定权限表，不提供自定义配置。

### 2. 邀请与加入

管理员填写姓名、邮箱和加入后的角色：

| 字段 | 要求 |
| --- | --- |
| 姓名 | 必填，用于成员识别 |
| 邮箱 | 必填、有效邮箱；已加入或存在有效邀请时提示，不重复创建 |
| 角色 | 必选，只有投放人员、财务人员；管理员身份通过交接获得 |

提交后生成待接受邀请，未接受前不授予权限。受邀人确认广告主和角色后接受或拒绝；正式服务必须核对登录身份与受邀邮箱一致。没有账号的先完成注册及邮箱验证，再返回邀请。

管理员可撤销待接受邀请；过期、拒绝或撤销后可重新邀请。旧失效邀请不能继续使用，也不能通过旧链接恢复已移除成员。已移除成员如需重新加入，应重新发起邀请并接受。

本稿沿用7天邀请有效期作为建议参数，正式期限待评审。Demo只模拟接收与接受，不发送真实邮件或提供真实身份校验。

### 3. 调整角色

管理员对已加入的普通成员选择投放人员或财务人员，保存后新权限生效。“待分配角色”的存量成员使用同一入口完成分配。管理员自身只能通过交接改变身份，不能直接改成普通成员。

角色变化后重新检查菜单、数据和操作权限。旧页面、收藏链接或已经打开的表单不能继续提交已失去权限的操作。前端隐藏入口之外，正式服务也必须在查询、导出和提交时校验权限。

### 4. 移除成员

仅管理员可移除普通成员，确认框展示具体姓名、邮箱及结果：失去当前广告主访问权限，但保留其创建的广告、财务和操作历史。移除不注销该人的登录账号，也不停止已有投放。

移除后旧会话不得继续读取或修改该广告主数据；页面提示权限已失效并引导联系管理员。

### 5. 管理员交接

只允许交接给本广告主已加入、身份有效且角色明确的成员，不能交给尚未接受邀请或已移除的人。

原管理员选择目标成员，并选择自己交接后的角色（投放人员或财务人员）。确认框展示目标姓名、邮箱、原管理员的新角色及立即失去成员管理权限的说明。

本期采用**原管理员明确确认后立即交接**，不新增审批链或待接任工作流。应先与对方沟通；取消不改变身份。确认成功后，对方成为唯一管理员，原管理员按所选角色生效；两人的变更应同时成功，不允许只改一半。再次刷新不恢复旧管理员。

记录交接操作人、时间、目标成员和交接后的角色。若管理员已无法登录，走运营核验，不允许普通成员自行抢占管理员。

## 五、与首页、通知、账号流程的关系

- 首页仍沿用已确认的结构。管理员和投放人员按自身可访问范围查看投放内容；充值及资金待办仅对有财务权限的成员提供操作入口。财务人员沿用资金工作台。
- 无操作权限时不提供可执行按钮；直接访问也应明确拒绝，不能通过通知、报表或帮助页绕过。
- 组织成员变更事件按现有通知方案通知管理员，角色变化后的界面同步更新；具体接收和保留规则与首页通知方案共同评审，不在本模块另建消息中心。
- 本人邮箱验证、找回密码和存量账号重置不改变原用户身份及成员关系；更换登录邮箱不能重新参与默认管理员排名。
- 不新增工作空间切换、逐计划授权、自定义角色、多级部门或额外审批流程。

## 六、Demo演示与验收重点

正常存量样例包含三类角色及一条“待分配角色”的过渡成员。绑定记录为明确标注的模拟数据，最早绑定者为Victor；恢复样例时故意把Linda排在列表首行，以验证不是按列表顺序分配。

左下角“演示工具”可切换成员视角，或打开“存量成员与管理员样例”：载入正常样例、绑定记录缺失样例。替换成员样例会重置当前浏览器的成员、邀请及成员操作记录，保留广告、余额、充值、报表和账号验证状态；操作前有说明。

重点验收：

1. 只有三类可分配角色，各自菜单、查询、导出和修改权限一致。
2. 最早成功绑定用户为管理员，不受注册顺序、申请顺序、列表顺序及其他广告主记录影响。
3. 绑定记录异常不随意选人，过渡成员不自动获得额外权限。
4. 邀请接受后才生效，过期和撤销不可接受，旧邀请不能恢复已移除成员。
5. 分配角色后按新权限生效；移除成员后旧访问失效，历史业务数据保留。
6. 交接取消不变化，成功后仅一名管理员，原管理员角色明确，刷新不恢复。
7. 新旧Demo版本及数据隔离；本次不修改冻结评审基线。

## 七、需研发与业务确认的实施输入

- 历史成功绑定时间及原始身份标识能否完整提供，精度是否足以判断先后。
- 无明确角色成员的原有效权限从哪里取得；无法核实时的核验处理人。
- 已完成交接的记录及异常归属如何核验，运营现有后台能否承接。
- 邀请邮件、登录身份校验、邀请有效期、权限变更对已登录会话的生效方式。

以上是实施依赖，**不改变“最早成功绑定者默认管理员”的已确认规则**。本次交付产品方案和前端交互样例，不修改真实存量用户、不接入真实邀请邮件、不代表服务端权限及迁移已完成。
