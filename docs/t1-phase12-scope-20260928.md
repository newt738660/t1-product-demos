# T1 一期／二期范围与入口清单

版本：2026-09-28 · 范围收敛与交互补全稿

## 1. 本轮结论

一期／二期合并评审，只展示当前需要设计、研发的能力。沿用已确认的开户绑定、CPD协同、RTB创编和报表规则，不因为旧Demo有入口就增加开发范围。本次不是生产系统上线，也不是对未确认排期的承诺。

左侧主导航仅保留：首页、广告投放、数据报表、财务管理。帮助中心和联系运营位于右上角账号菜单，首页介绍卡也可到达相关帮助文章。

独立创意中心／创意仓库、账户与组织管理移出一期／二期：菜单、首页快捷入口、通知中的成员权限事件同时移除。创意仍在对应计划／广告组下创建、编辑、查看审核及版本，不删除投放所必需的创意能力。

充值属于财务管理，不再单设一级菜单。顶栏保留快捷充值，与财务页使用同一流程。

## 2. 范围边界

|模块|一期／二期保留|暂不展示或另行确认|
|---|---|---|
|首页|未关联、申请审核中、驳回、已关联无投放、已有投放；引导、介绍、待处理入口|不恢复内部开发说明；计划状态和近期排期暂沿用现有结构，其业务价值仍可后续讨论|
|广告投放|CPD／RTB列表、筛选、计划／组／创意详情；RTB创编编辑；CPD受控创意修改与版本|CPD自助下单、CPD价格／库存／排期／启停编辑不开放|
|数据报表|RTB／CPD查询、指标、趋势、对象明细、导出、归档历史|不新增转化归因、自动优化或自定义报表搭建器；现有多维粒度沿用，不代表新增接口承诺|
|财务管理|余额、发起充值、凭证、充值历史及详情、审核结果、RTB消耗历史、对应报表|不新增发票、退款、授信、合同结算系统；CPD合同费用不混入RTB钱包消耗|
|帮助中心|快速入门、RTB、CPD、报表、充值、创意审核六篇基础指南及联系运营|不新增工单系统、在线客服、文章管理后台|
|右上角账号|用户名、帮助中心、联系运营、退出、更换登录账号|不提供企业／广告主切换、成员邀请、角色权限管理、组织设置|
|通知|投放与审核、资金与账务、账户与服务；摘要、全部、详情、对应落点|三期成员权限通知移除；消息已读不能代表业务问题已解除|
|前置流程|现有注册登录、开户／绑定、邀请码确认、申请结果、驳回重提|邮箱验证与存量迁移仍按独立方案评审，不在本轮擅自当成已上线；新注册激活和重置邮件仍需后端验证|

“更换登录账号”只表示退出后重新登录，不代表三期多组织／多广告主切换。未关联广告主也能读帮助、联系运营；访问投放、报表、财务时进入开户／绑定引导或申请状态，不展示别人的业务数据。

## 3. 首页各状态及落点

|状态|首页内容|主行动与结果|辅助入口|
|---|---|---|---|
|未关联广告主|欢迎说明及RTB／CPD／报表介绍|创建或绑定 → 选择新开户／申请绑定／邀请码 → 表单或确认浮层|介绍卡 → 对应指南；联系运营 → 咨询浮层|
|新开户审核中|审核中与结果说明|查看申请 → 名称、类型、时间、进度浮层；可撤销开户申请 → 二次确认 → 回到未关联|联系运营；指南可正常阅读|
|绑定申请审核中|审核中与结果说明|查看申请 → 绑定申请信息，不照搬开户撤销按钮|联系运营；指南|
|开户／绑定驳回|驳回原因|修改并重新申请 → 回填原申请、展示原因 → 提交 → 审核中|联系运营；指南|
|已关联无投放|首次投放引导|创建RTB → 三层创编 → 提交 → 对应计划；CPD → 联系运营|指南；财务可充值，列表与报表为空态|
|有RTB／CPD／两种投放|当前计划状态、需要处理的问题、排期|异常处理 → 对应计划／广告组／预算；状态数量 → 对应计划集合 → 详情|报表、资金、帮助|
|有投放且余额不足|当前阻断及充值入口|资金 → 充值 → 待审核记录；未到账不消除余额不足|通知保留历史事件|
|正常投放，无紧急事项|正常计划状态与排期|进入计划／报表，不保留空的紧急待办模块|帮助、资金|
|通知为空|首页业务不变|铃铛 → 暂无通知；全部通知可打开空列表|不会因无通知隐藏业务问题|

首页RTB、CPD和报表介绍卡均是完整按钮，鼠标、键盘都能进入对应指南。指南不只是再次解释卡片标题，而是包含操作步骤、业务边界和下一步按钮。

## 4. 关键入口清单

|入口|打开方式|展示内容|下一步及返回|
|---|---|---|---|
|首页RTB介绍卡|帮助文章页|三层创建、预算排期、审核与可投条件|创建RTB；未关联先走开户；返回帮助中心|
|首页CPD介绍卡|帮助文章页|运营配置、广告主创意协同、版本规则|联系运营咨询浮层；返回帮助中心|
|首页投放效果卡|帮助文章页|日期、类型、指标、明细和归档口径|打开报表；未关联则开户引导|
|帮助中心六张卡|对应文章页|完整基础步骤与注意事项|对应业务动作、联系运营、返回帮助中心|
|联系运营|浮层|已有业务沟通渠道说明；咨询主题、账号、广告主、相关对象和描述模板|复制咨询内容 → 用户在已有业务群发送；关闭或查看指南|
|右上角用户名／头像|悬停或点击下拉；键盘可聚焦|登录身份、帮助、联系运营、换账号、退出|点击外部／Escape关闭；移动端点击打开|
|退出／更换登录账号|二次确认浮层|说明未提交表单不保存、广告不停止|取消继续使用；确认清除登录态并到登录页|
|铃铛|浮层|最近5条、未读数、类别、摘要、时间|点击消息详情；全部已读；查看全部通知；点击外部／Escape收起|
|全部通知|宽浮层|类别、已读／未读筛选、列表和空态|点击详情；返回通知中心；关闭|
|通知详情|浮层|当时事件、当前状态、关联对象|创意／版本、计划、充值记录、资金、报表或申请；账户关联成功返回首页|
|顶栏／财务充值|同一充值浮层|金额、币种网络、收款信息、凭证、校验|提交 → 待审核充值记录；金额不足／无凭证保持原表单并提示|
|充值记录查看|详情浮层|申请、金额、凭证、审核时间与原因|凭证预览；驳回后重新上传；关闭返回记录|
|消耗记录|财务页页签|日期、RTB计划、花费，含归档历史；查询、分页、无数据|查看对应报表 → 带同一天、计划、RTB过滤条件|
|计划内创意入口|原详情／编辑／预览流程|所属计划、组、审核、生效版和待审版|保留提交、取消、返回及审核限制；不是独立素材仓库|

联系运营的边界：本版不编造TG用户名、邀请链接、客服邮箱或承诺已发工单。已有业务群为办理渠道，页面提供可复制咨询信息。若希望一键直达，需业务提供并维护正式联系方式；这是内容配置项，不要求设计师猜一个地址。

## 5. 财务与报表口径

- 充值申请、审核通过的到账、广告消耗分开表达，待审核充值不增加余额。
- 财务消耗记录为RTB逐日、逐计划花费，使用与报表相同的底层样例记录，不用合同额推算效果花费。
- 查询默认包含归档对象的有效历史记录；当前归档不会删掉过去花费。
- CPD展示投放效果，合同金额在投放详情查看；结算问题联系运营，不假装本期已经有结算后台。
- 财务页显示“已提供周期内RTB消耗”，不拿固定样例冒充实时本月值；超出已有数据周期明确提示，不当作0。
- Demo的付款数据仅供走查，收款区域明确不接收真实转账；生产需接实际收款配置与审核服务。

## 6. 多状态演示与正式功能隔离

正式视角不显示状态切换；评审链接携带review=1，左下角显示折叠的“演示工具 · 非产品功能”。选择器提供12种状态，包括开户／绑定不同申请类型、正常／受阻投放及通知为空。

评审模式使用独立标签页存储，切换重置的是该评审模式下的样例，不覆盖普通Demo记录。刷新保留本次评审操作；切换状态重新载入基准样例。所有状态均可继续点开入口验证，不只是替换标题的截图模式。

设计与研发不得把演示工具列入生产需求；正式产品状态来自账户、申请、投放与财务数据。不要把页面整个等比缩小来适配笔记本，按实际浏览器窗口检查字号与控件。

## 7. 交付与验收边界

本轮交付为收敛后的前端Demo、范围清单与入口说明。既有开户、RTB创编、CPD双版本等路径继续保留；未改Figma，没有自动发送运营消息、真实充值、审核或邮件。

验收重点：本期入口都有可读页面、浮层或行动；三期入口不再在菜单、快捷入口或通知中泄漏；未关联状态有阻断；待审与驳回有后续操作；财务与报表金额一致；账号菜单可退出；空态与多状态可复现。静态稿和Demo通过不等于生产接口及权限验收通过。

需要后续业务／研发明确但不应由UI自行补空：正式运营联系方式、实际通知投递接口、邮箱验证迁移上线批次、财务收款及审批配置、SSP尚未确认的预算和状态映射。API for AI Agent另行评审，不因本次Scope收敛自动加入左侧导航。
