## 使用

- DSP 地址加 `?demo=1&review=1`，左下角展开“演示工具”，选择“Demo版本（非产品功能）”。
- 登录页加 `?review=1` 也可切换版本。
- 普通展示地址不带 `review=1`，不会出现演示工具。
- 选择会进入明确版本路径，不将老地址自动升级为新版本。
- 未提交的 RTB 编辑离开前有确认提示。
- 每版拥有独立的业务 HTML、脚本、样式和图片副本；登录与业务跳转保持版本内相对路径。
- `storage.js` 必须在业务脚本前加载。各版本的 localStorage/sessionStorage 均按版本前缀隔离；清空单版存储不影响其他版本。根目录数据不迁移、不清空。
- 冻结代码不代表冻结日期或用户自己的演示操作；业务代码仍按原有时间、样例逻辑运行。

## 增加后续版本

1. 将已评审版本完整复制到新的固定目录（不要共享会继续修改的业务资源）。
2. 保留相对业务跳转，并在每个 HTML 头部先引入 `../../versioning/storage.js`。
3. 评审入口引入 `../../versioning/switcher.js`，在 `versioning/versions.json` 追加准确的路径、名称和就绪状态，不复用既有版本ID。
4. 冻结业务后记录对应文件校验值；禁止为掩盖意外改动而重建旧校验值。
5. 验证普通链接、版本下拉、未保存提示、登录跳转和双向数据隔离，再发布。
